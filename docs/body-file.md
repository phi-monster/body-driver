# 身体文件:这台机器量到的自己

驱动开机时量自己:每条胳膊怎么动、眼长在哪、爪子怎么合。量到的东西写进一个文件,跟着这台机器走。下次开机先装回,推一下核对;对得上就不再从零量。对不上的那几格才重量,新量的和旧的合在一起(取中位数),不覆盖。

文件里只有身体。世界、任务、东西在哪,一概不存。

## 1. 用法

```
body_driver --listen 9080 --out body.json            # 第一次:从零量,量完写进 body.json
body_driver --listen 9080 --in body.json --out body.json   # 以后:装回、核对、合成、写回
```

`--in` 和 `--out` 是同一个参数的两个名字:给了就装回(文件在的话),量完写回同一个路径。删掉文件 = 下一次从零量。

同一个路径旁边还有几个文件,是开机前半段(按关节量运动学)存的:

| 文件 | 是什么 |
|---|---|
| `<路径>` | 身体文件本身(JSON) |
| `<路径>.kin.txt` | 每条臂的运动学、每一节的表面点、不动的眼、桌面;干活时关节到过的范围长了、或记下一个尽头,就写回 |
| `<路径>.kin.txt_arm<k>.bmp` | 第 k 条臂扫描起点那一格的腕眼图,下次开机核对"它挪没挪"用 |
| `<路径>.kin.txt_world.bmp` | 不动的眼在那一刻的图 |

## 2. 钥匙:是不是同一具身体

文件里的 `key` 记着这具身体报上来的形状:几条臂、几个抓握读数组、每台相机的画幅(带不带深度)、位姿和关节读数的键名。开机时这台机器报的形状和钥匙对不上,就不装,从零量,开机日志里照实说。

前半段那份(`.kin.txt`)另有一把钥匙:几台相机、每台画幅、几组关节读数、每组几个数、几个抓握通道、关节读数的字段名。装回以后,每条臂按关节命令回到存的参照读数,停稳了拍一张,和存的图比:配上的点至少 10 个、位移中位不到 1 像素,才算没挪。哪一项不过,就说哪只挪了多少,从零量。

## 3. 里面有什么(身体文件,JSON)

| 键 | 是什么 |
|---|---|
| `key`、`method_ver` | 钥匙;量法版本(量身体的代码一改就加一,版本对不上的格重量) |
| `arms`、`cams`、`per_arm` | 几条臂、几台相机、每条臂几个位姿通道 |
| `noise_ver`、`ee_noise`、`rot_noise`、`jaw_noise`、`settle` | 静止时读数抖多少(位置、朝向、抓握),和量它的方法版本;一条命令发出后读数要几拍才稳 |
| `amp`、`delivered`、`seen`、`cam_frac` | 每个通道:推多大走得出来又看得见、实到多少、有没有一台眼看见它动、它一动每台眼的画面变多少 |
| `cam_on_arm`、`world_cam`、`jaws`、`pic_floor` | 每条臂上长着哪台相机;不动的那台;每条臂几个抓握通道;每台相机静止时的画面噪声 |
| `amp_hist`、`deliv_hist`、`measured_times` | 历次量到的(每格最多留 7 次,现值取中位数);量过几次 |
| `hands` | 每条臂每个抓握通道:合空和张开时的读数、合几步、量的时候的位姿;它在各台眼里的握区(每一瓣的框、手指像素的游程) |
| `tables` | 响应表(推哪个通道、画面里的东西往哪走);只存不装回,因为它是就地学的,跟错东西就学反 |
| `schema` | 身体图:在各个位姿下,自己的零件在每只眼的哪儿 |

- 数写出去、读回来,一个比特不差。不是有限数的写成 `null`(读回来是 NaN),是哪几格照实印在日志里。
- 噪声取历次最大(只放大不缩小);幅度和实到取历次中位数。
- 09-30 以前的文件没记"每条臂几个抓握通道",读到这种文件,开机要重量,不按一个去猜。

## 4. 不要手改

这个文件是机器自己量的。手改一个数,就是替它拍了一个数,和"不许拍数"那条规矩冲突。要重量就删掉,或者换一个路径。
